## The 8 assets that did not come out, and why

All of them are **uploaded documents, not images**: one `.odt` and seven `.md`
(including this house's own logs). In the conversation JSON they arrive as
`file_kind: "blob"` with **no url field of any kind** and a `path` of
`/mnt/user-data/uploads/...` — a container path, not an address.

Eight endpoint shapes were tried against a real blob uuid, on both API roots
(`/api/{org}/files/…` and `/api/organizations/{org}/files/…`): bare, `/preview`,
`/thumbnail`, `/download`, `/content`, `/document`, `/raw`, and a `?uuids=`
query. **404 on every one.** claude.ai does not serve blob uploads through its
web API.

Before this run the extension *guessed* a `/preview` URL for those and reported
"download failed or unsupported" when the guess 404'd — taking the blame for a
platform limitation, in an archive someone keeps for years. It now says what is
actually true.

## Two defects the proof found that no test would have

1. **The filename.** A plain (media-free) export offered the blob UUID in the
   Save-As dialog instead of the typed name — the last code path still using the
   downloads API, which receives a `blob:` URL and loses the name. Every format
   now goes through the anchor. The `downloads` permission became unused and was
   removed.
2. **The extension, substituted by the machine.** A `.json` export landed as
   `.customization` and a `.html` one as `.htm`. Not ours: Chrome rewrites a
   download's extension from the Windows MIME registry, and this machine carries
   `HKCU\…\Content Type\application/json → .customization` (written by some
   installer) plus `HKLM\…\text/html → .htm`. Downloads now go out as
   `application/octet-stream`, which is mapped nowhere, so the typed name
   reaches disk character for character on any machine.

## How to re-run this

```
python tests/verify-export.py <file.zip|file.html|file.md> [...]
python tests/verify-export.py --latest
```

Exit 0 = every check green. The verifier is proven to bite: five synthetic
failure modes, including the exact 2026-08-06 signature, all exit 1.
